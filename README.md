## Задача: 
На вход даётся видеозапись транспортного потока с камеры видеонаблюдения. Камера расположена статически, ракурс не изменяется.
С помощью детектора на основе нейронных сетей необходимо детектировать транспортные средства (ТС). На выходе детектора – bounding box’ы (bbox, ббокс).
Разрешается и рекомендуется использовать предобученные модели.

• Реализовать трекер ТС <br>
• Реализовать подсчет ТС по двум направлениям (к камере и от камеры)<br>
• Реализовать визуализацию детектора и трекера. Визуализатор должен отображать bounding box’ы и треки.

### Детектор
  >   В качестве детектора использовал предобученную модель YOLO26. Потому что они очень
>   хорошо себя показывают прямо "из коробки". Из всего семейства YOLO взята самая
>   точная модель YOLO26 и ее самая маленькая конфигурация nano (YOLO26n) т.к нам
>   важна скорость на CPU.
>
>   YOLO26n не быстрее YOLOv8n (1.7ms vs 1.47ms), но точнее на 4% по mAP, эти 0.23мс
>   нам погоды не сделают на CPU, а точность все-таки важна. Детектор обрабатывает
>   каждый кадр и возвращает bounding box, класс и уверенность для каждого
>   обнаруженного объекта. Классы COCO: car (2), motorcycle (3), bus (5), truck (7)
>   (Все авто ТС). Порог уверенности: 0.15 — намеренно низкий, т.к трекер (ByteTrack)
>   использует и слабые детекции для поддержания треков. Модель экспортированна в onnx<br>, для лучшей работы на сpu.
  > 
### Трекер
  > Трекер представляет собой комбинацию **ByteTrack + фильтр Калмана**. Вообще я бы
> использовал бы встроенный трекер в YOLO, в котором уже реализован и ByteTrack и
> BoT-SORT, но в задании под "реализовать трекер" я понимаю самому реализовать
> архитектуру.
>
> Так что был выбран алгоритм **ByteTrack**, а не, например, SORT или BoT-SORT.
> SORT - быстрый, но не справляется с окклюзиями, а BoT-SORT и прочие более
> точные алгоритмы, чем ByteTrack, очень медленные и будут съедать много
> ресурсов CPU. Так что ByteTrack - золотая середина. Быстрый и неплохо
> справляется с окклюзиями из-за фильтра Калмана и двухэтапного матчинга.
>
> Матчинг был реализован по алгоритму **Jonker-Volgenant** - он тоже своего рода
> золотая середина: он быстрый и достаточно хорошо себя показывает, бережем
> ресурсы CPU. Тоже самое и с фильтром Калмана.







### Cчетчик
> Подсчет трека идет при выполнении критериев:
>
> 1) Возраст трека ≥ 20 кадров (отсеиваем ложные детекции)
>
> 2) Смещение от стартовой точки > 70 и кадров с движением > 6 px (для задачи это,
>    конечно, бесполезно, так как в кадре нет стоячих машин в конкретном видео,
>    но если масштабировать, то это нужный параметр)
>
> 3) Устойчивость направления > 70% - на случай, если "поменяются треками" машины,
>    едущие в противоположных направлениях при окклюзии.
>
> После засчитывания трека определяем направление покадровым голосованием.
> Поскольку на нашем видео дорога расположена по диагонали, то направление кадра
> считаю по диагональной проекции: `(Δx − Δy)`.
>
> Если мы захотим загрузить видео с другой камеры (например, где машины едут
> горизонтально или вертикально), в счетчике есть параметры: 'x', 'y' или
> 'diagonal'. Для нашего видео стоит параметр 'diagonal'.



### Визуализатор
> Средствами OpenCV отображаются на кадре bboxes и tracks. Пока ТС не посчитан,
> у боксов и треков будет серый цвет. Когда авто "посчитано", трек и бокс
> становится зеленым.
>
> Обработанное видео сохраняется в директорию output. Это можно отключить в
> конфиге или при запуске из командной строки.


## Структура проекта:
```bash
VehicleTrack/
├── main.py              # Основной пайплайн
├── config.py            # Конфигурация (пути и др. параметры)
├── detector.py          # Детектор ТС 
├── tracker.py           # ByteTrack трекер + Kalman Filter
├── counter.py           # Подсчёт ТС по направлениям
├── video.py             # Обёртка над VideoCapture
├── utils/
│   └── geometry.py      # IoU 
├── model/
│   └── yolo26n.onnx     # Модель YOLO (ONNX для CPU)
├── data/
│   └── test_video.mp4   # Тестовое видео
├── output/              # Папка для результатов
├── examples/
│   └── sample.gif       # Пример работы
├── requirements.txt     # Зависимости Python
├── Dockerfile           # Docker-образ
├── docker-compose.yml   # Docker Compose
└── README.md
```





## Установка 

```bash
# Клонировать репозиторий
git clone https://github.com/alkonorov/VehicleTrack.git
cd VehicleTrack
```
### Создать виртуальное окружение
```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
# venv\Scripts\activate   # Windows
```
### Установить зависимости
```bash
pip install -r requirements.txt
```
### Подготовить данные
Положить модель yolo26n.onnx в папку model/ (если ее там нет)<br>

**Положить видеофайл в data/test_video.mp4 (или указать свой путь в config.py → VIDEO_PATH)!!**

# ЗАПУСК
## Запуск с отображением видео (на CPU)
```bash
python main.py -v data/test_video.mp4 -o output/result.mp4
```
Будет обрабаывается видео в окне с отрисованными bbox и треками, а обработанное видео запишется в папку output

### Справка по  остальным аргументам
```bash
python main.py --help
```


| Аргумент     | Коротко | По умолчанию           | Описание                              |
|--------------|---------|------------------------|---------------------------------------|
| `--video`    | `-v`    | из `config.py`         | Путь к входному видео (test_video.mp4)|
| `--model`    | `-m`    | из `config.py`         | Путь к модели YOLO                    |
| `--output`   | `-o`    | `output/result.mp4`    | Путь для сохранения результата        |
| `--device`   | `-d`    | `cpu`                  | Устройство: `cpu` или `cuda`          |
| `--no-display` |     | `False`                | Не показывать окно (для сервера)      |

## Запуск через Docker (без отображения)
